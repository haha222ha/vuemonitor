## 一、系统定位

**一句话定义**：将人生决策问题结构化，并自动筛选为可变现内容资产的生成系统。

**核心目标**：不是告诉用户"发生了什么"，也不是给用户建议，而是识别"哪些决策问题正在变得值钱"，并将其筛选为可进入内容生产流水线的选题资产。

**系统本质**：选题生成的上游决策过滤器，不是决策AI，而是"哪些人生问题值得包装成内容"的筛选器。

**对标对象**：CB Insights / Gartner / 36氪研究院 / 艾瑞咨询

全部通过 → 进入选题生成流程（Prompt二~八）

    ↓
选题系统（topic.json，含decision_layer）
    ↓

## 六、核心机制详解

### 6.1 去重机制

```
新选题输入
    │
    ▼
第1步：精确匹配
  读取topics/ + archive/ 所有topic_name
  完全相同 → 拒绝
    │
    ▼ 通过
第2步：关键词比对
  3个以上相同 → 拒绝
  2个相同 → 进入角度比对
  0-1个相同 → 通过
    │
    ▼ 2个相同
第3步：角度比对
  角度相同 → 拒绝
  角度不同 → 通过，标记为系列选题
    │
    ▼
通过 → 存入topics/
拒绝 → 记录到rejected/
```

### 6.2 优先级排序

```
优先级分数 = 机会评分 × 新鲜度系数 × 生命周期权重
```

| 新鲜度 | 系数 | 生命周期 | 权重 |
|--------|------|----------|------|
| 1天内 | 1.2 | 早期 | 1.3 |
| 2-3天 | 1.0 | 爆发期 | 1.0 |
| 4-7天 | 0.8 | 饱和期 | 0.6 |
| 8-14天 | 0.5 | | |
| 15-30天 | 0.3 | | |
| 30天+ | 0.1 | | |

### 6.3 决策型选题5问筛选（V3新增）

| 问题 | 判断标准 | 不通过后果 |
|------|----------|-----------|
| 有没有足够多的人在焦虑？ | 目标人群>100万 | 不值得做内容 |
| 焦虑能不能结构化为内容？ | 能拆3+个独立维度 | 内容无法生产 |
| 内容能不能卖钱？ | 用户有付费意愿 | 无法变现 |
| 能不能进入内容工厂？ | 能生成HTML+PDF+小红书 | 生产成本过高 |
| 能不能拆成10天内容？ | 至少10个不同角度 | 内容深度不够 |

5个全部通过 → 进入topics/
任一不通过 → 记录到rejected/

### 6.4 选题生命周期

```
fresh ──→ queued ──→ consumed ──→ archived
 │          │           │           │
 │          │           │           └─ 移入archive/
 │          │           └─ 用户确认"归档"后
 │          └─ 写入export/topic.json时
 └─ 刚生成时

特殊情况：
- 7天未消费 → 标记expired
- 30天未消费 → 移入archive/，标记abandoned
- 用户手动标记 → 直接archived
```

## 十、系统设计原则

1. **选题是核心资产**：选题库比内容产出更有价值
2. **三层解耦**：采集、筛选、生产各层独立，通过JSON接口对接
3. **决策过滤器在上游**：不是所有信号都值得做内容，5问筛选确保质量
4. **数据驱动**：所有决策基于量化评分，不靠主观判断
5. **闭环管理**：选题从生成到归档有完整生命周期追踪
6. **去重保证**：关键词+角度双重去重，确保选题不重复
7. **信息不丢失**：export/topic.json传递完整选题信息（含决策层）
8. **用户确认归档**：内容工厂不能自动修改中转站，需用户确认
9. **商业情报可售卖**：选题库本身就是可独立交付的商业产品
10. **全场景覆盖**：6大决策领域×N子场景，不限于AI副业

| 变更项 | V2 | V3 | 影响 |
