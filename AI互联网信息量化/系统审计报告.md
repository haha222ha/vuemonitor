# V3系统审计报告 — 逻辑漏洞与设计Bug

> 审计日期：2026-05-20
> 审计范围：全系统10个Prompt + 中转站 + 内容工厂 + 数据流

---

## 🔴 严重问题（必须修复）

### BUG-01：数据流断裂 — Prompt十的输出无法进入下游

**位置**：九、输出格式规范.txt + 0-中转站总控.txt

**问题**：
- V3数据流定义为：`互联网信号 → Prompt十 → Prompt一~八 → Prompt九 → 中转站`
- 但Prompt十的输出格式（决策情报信号）与Prompt二~八的输出格式（趋势信号/评分表/心理分析）**完全不同**
- Prompt九只定义了"如何将Prompt二~八的自由文本转换为JSON"，没有定义"如何将Prompt十的输出与Prompt二~八的输出合并"
- **结果**：Prompt十的decision_layer、content_engine_bridge、risk_matrix字段无法被正确组装到topic.json中

**影响**：V3核心升级的3个新字段组实际上无法进入topic.json

**修复方案**：
1. 在Prompt九中增加"合并规则"：明确Prompt十的输出作为"骨架"，Prompt二~八的输出作为"填充数据"
2. 或：让Prompt十直接输出完整topic.json，跳过Prompt二~八（但这会丢失量化评分）
3. 推荐方案：定义"决策型选题"和"趋势型选题"两条独立的数据流

---

### BUG-02：export/topic.json格式未更新为V3

**位置**：0-中转站总控.txt 规则5 + templates/export_interface.txt

**问题**：
- export/topic.json仍是V2格式，只包含：topic_name, category, target_platform, target_audience, opportunity_score, lifecycle_stage, commercial_paths, user_psychology, content_angles
- **缺少V3新增字段**：decision_layer, content_engine_bridge, risk_matrix, score_breakdown
- 内容工厂无法获取persona_decision_map（不同人群策略）、viral_hook（爆款标题）、monetization_hook（卖货切入点）

**影响**：内容工厂生产时无法利用决策层数据，V3升级对内容工厂无效

**修复方案**：更新export/topic.json格式，包含完整V3字段

---

### BUG-03：5问筛选执行点不明确（重复执行/遗漏风险）

**位置**：一、系统总目标 + 十、决策场景分类 + 0-中转站总控

**问题**：
- 5问筛选在3个文件中都有定义：
  - 一、系统总目标：核心目标部分
  - 十、决策场景分类：选题筛选5问部分
  - 0-中转站总控：规则1决策型选题额外要求
- **问题**：5问筛选应该在哪个环节执行？
  - 如果在Prompt十执行 → 中转站再次执行是重复
  - 如果在中转站执行 → Prompt十输出的信号可能没通过筛选
  - 如果两边都执行 → 标准可能不一致

**影响**：可能导致未通过筛选的选题进入topics/，或通过筛选的选题被中转站拒绝

**修复方案**：明确5问筛选只在Prompt十执行，中转站只验证can_convert_to_topic=true

### BUG-04：优先级排序公式未包含V3新字段

**位置**：0-中转站总控.txt 规则4

**问题**：
- 当前公式：`优先级分数 = 机会评分 × 新鲜度系数 × 生命周期权重`
- **未使用V3新增字段**：
  - content_engine_bridge.compatibility_score（内容工厂兼容度）
  - content_engine_bridge.monetization_potential（变现潜力）
  - decision_layer.seasonal_peak（季节性高峰）
- 季节性选题（如高考志愿填报）在淡季和旺季的优先级分数相同

**影响**：季节性选题无法在高峰期获得更高优先级

**修复方案**：
```
优先级分数 = 机会评分 × 新鲜度系数 × 生命周期权重 × 季节系数 × 兼容度系数

季节系数：
- 当前处于季节性高峰期内：1.5
- 距离季节性高峰<30天：1.2
- 非季节性选题：1.0
- 季节性高峰期已过：0.3

兼容度系数 = content_engine_bridge.compatibility_score / 100
```

### BUG-05：生命周期阶段定义不一致

**位置**：topic_template.json vs 0-中转站总控.txt

**问题**：
- 中转站总控定义的生命周期权重：早期(1.3) / 爆发期(1.0) / 饱和期(0.6)
- topic_template.json示例中使用：`"lifecycle_stage": "爆发期"` ✅
- 但架构文档和export_interface中使用：`"lifecycle_stage": "早期爆发"` ❌
- Prompt三（机会量化）输出：早期/爆发/饱和
- Prompt七（爆发预测）输出：是否正在进入爆发期（是/否）

**影响**：AI可能输出"早期爆发"等非标值，导致生命周期权重无法匹配

**修复方案**：统一为3个标准值：early / burst / saturated（或中文：早期/爆发期/饱和期），所有Prompt和模板必须严格使用

## 🟡 中等问题（建议修复）

### BUG-06：Prompt十输出格式与Prompt九转换规则不匹配

**位置**：十、决策场景分类与选题映射.txt vs 九、输出格式规范.txt

**问题**：
- Prompt十的输出格式中"人群决策映射"只有1个persona
- Prompt九的映射规则中persona_decision_map是数组`[]`
- Prompt十输出格式中"商业化路径"是4个固定类型（虚拟产品/课程/工具/信息差产品）
- Prompt九的映射规则中commercial_paths是数组，但没有指定数量

**影响**：AI输出格式可能不一致，导致JSON转换失败

**修复方案**：统一Prompt十和Prompt九的格式定义

---

### BUG-07：去重规则未考虑决策型选题的特殊性

**位置**：0-中转站总控.txt 规则2 + templates/dedup_archive_rules.txt

**问题**：
- 当前去重基于：topic_name精确匹配 + keywords比对 + content_angles比对
- **决策型选题的特殊性**：同一决策场景可能针对不同persona生成多个选题
  - 例："高考志愿填报"针对"高考生家长"和"高三学生"是两个不同选题
  - 但keywords可能高度重叠（高考、志愿、专业、选择）
  - 按当前规则会被拒绝

**影响**：决策型选题的合理多角度内容被错误去重

**修复方案**：
- 增加persona维度去重：如果decision_layer.persona_decision_map[].persona不同，允许keywords重叠
- 或：增加decision_type维度：不同core_decision_type的选题不互相去重

---

### BUG-08：季节性选题的生命周期管理不合理

**位置**：0-中转站总控.txt 规则4

**问题**：
- 规则：生成超过30天未消费 → 移入archive/并标记abandoned
- 但季节性选题（如高考志愿填报）的生命周期是：
  - 3-5月：生成（备考期）
  - 6-7月：爆发（出分后）
  - 8月后：需求骤降
- 如果3月生成，7月才消费 → 超过30天被标记abandoned
- 但实际上7月正是最佳消费时机

**影响**：季节性选题被错误废弃

**修复方案**：
- 季节性选题的过期判断基于seasonal_peak而非固定30天
- 规则：如果当前处于seasonal_peak期间或前30天内，不标记abandoned

### BUG-09：情报产品线未更新V3新增产品

**位置**：0-中转站总控.txt 可售卖情报产品部分

**问题**：
- 架构文档定义了7类产品（含V3新增：决策分析报告、专业前景数据库、行业选择决策报告）
- 但中转站总控只定义了4类产品（V2版本）
- intelligence/目录结构也没有新增产品的文件命名规则

**影响**：V3新增情报产品无法生成

**修复方案**：在中转站总控中增加3个新产品定义和文件命名规则

### BUG-10：topic_template.json的source字段示例不一致

**位置**：商业情报中转站/templates/topic_template.json

**问题**：
- source.prompt_id = "十"（决策场景分类）
- source.prompt_name = "决策场景分类与选题映射"
- source.converted_by = "九、输出格式规范"
- **问题**：如果选题是由Prompt二~八生成的（非决策型），prompt_id应该是"二"~"八"
- 但模板只展示了Prompt十的示例，没有展示Prompt二~八的示例

**影响**：AI生成非决策型选题时可能错误填写source字段

**修复方案**：在模板注释中说明不同Prompt对应的source值

**位置**：十、决策场景分类与选题映射.txt 末尾字段映射表

**问题**：

**位置**：0-中转站总控.txt 规则1

**问题**：

## 🎯 核心结论

**V3升级的本质问题**：

> 你把"决策系统"加到了系统中，但没有重新设计数据流来适配它。

当前V3架构：
```
互联网信号 → Prompt十 → Prompt一~八 → Prompt九 → 中转站 → 内容工厂
```

实际能工作的数据流（V2）：
```
互联网信号 → Prompt二~八 → Prompt九 → 中转站 → 内容工厂
```

**Prompt十目前是"悬空"的**：它输出了决策信号，但这些信号无法与Prompt二~八的输出合并，也无法直接进入topic.json。

**正确的V3架构应该是两条独立数据流**：

```
数据流A（趋势型选题）：
互联网信号 → Prompt二~八 → Prompt九 → topic.json → 中转站 → 内容工厂

数据流B（决策型选题）：
互联网信号 → Prompt十 → Prompt九(决策版) → topic.json(含decision_layer) → 中转站 → 内容工厂
```

两条流共享：中转站、去重、评分、导出、内容工厂。
