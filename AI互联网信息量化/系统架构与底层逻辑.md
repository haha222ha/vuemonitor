# AI副业情报决策系统 — 架构与底层逻辑

## 一、系统定位

**一句话定义**：从互联网信息中识别"哪些副业方向真正能赚钱"，并将其筛选为可进入内容生产流水线的选题资产。

**本质**：用户给一个副业方向，系统自动执行从选题→机会判断→内容产出的全流程，中间不停顿、不询问、不等待确认。

**聚焦领域**：仅做D层经济决策——副业/AI变现/知识付费/轻创业/虚拟产品/平台红利。

## 三、底层设计逻辑

### 3.1 核心商业逻辑

```
互联网信号 → 筛选"哪些副业方向值得包装成内容" → 内容资产 → 变现
```

系统不是"告诉用户发生了什么"，也不是"给用户建议"，而是**将副业信号转化为可售卖的内容资产**。

### 3.2 五问筛选机制

每个副业信号必须通过5问筛选才能进入生产流水线：

| # | 筛选问题 | 通过标准 |
|---|---------|---------|
| 1 | 有没有足够多的人想做？ | 目标人群>100万 |
| 2 | 能不能被结构化为内容？ | 能拆3+个维度 |
| 3 | 内容能不能卖钱？ | 用户有付费意愿 |
| 4 | 能不能进入内容工厂？ | 能生成HTML+PDF+小红书10天内容 |
| 5 | 能不能拆成10天不重复的内容？ | 至少10个不同角度 |

5问全部通过 → 高价值选题，进入topic.json；任一不通过 → 不进入内容生产系统。

### 3.3 机会判断三档分级

| 判断 | 分数 | 处理 |
|------|------|------|
| RECOMMENDED | ≥35分 | 写入topics/，优先生产；纳入会员周报TOP3；写入opportunity_db |
| CAUTION | 25-34分 | 写入topics/但标记risk_flag=true，优先级×0.7降级 |
| AVOID | <25分 | 不写入topics/，直接写入risk_db风险淘汰库 |

### 3.4 优先级排序公式

```
优先级分数 = 机会评分 × 新鲜度系数 × 生命周期权重 × 季节系数 × 兼容度系数
```

| 因素 | 计算规则 |
|------|---------|
| 新鲜度 | 1天内1.2 → 2-3天1.0 → 4-7天0.8 → 8-14天0.5 → 15-30天0.3 → 30天+0.1 |
| 生命周期 | 早期1.3 → 爆发期1.0 → 饱和期0.6 |
| 季节性 | peak期间1.5 → peak前30天1.2 → 非季节性1.0 → peak后0.3 |
| 兼容度 | compatibility_score / 100 |

## 四、数据流详解

### 4.1 阶段一：选题生成

```
用户说方向
    ↓
Step 1.1  读取方向参数（子场景/数量/限定方向）
    ↓
Step 1.2  Prompt十：决策场景分类与选题映射
          → 识别副业信号 + 5问筛选
    ↓
Step 1.3  Prompt三：机会量化
          → 10维度评分 → opportunity_score
    ↓
Step 1.4  Prompt七：爆发预测
          → 生命周期阶段 + 时间线预测
    ↓
Step 1.5  Prompt九：输出格式规范
          → 自由文本 → 结构化JSON（含decision_layer + content_engine_bridge + risk_matrix）
    ↓
Step 1.6  机会判断Prompt
          → RECOMMENDED / CAUTION / AVOID
    ↓
Step 1.7  写入中转站topics/（仅RECOMMENDED/CAUTION）
```

### 4.2 阶段二：内容生产

```
export/topic.json
    ↓
Step 2.1  导出到内容工厂（status→queued）
    ↓
Step 2.2  Prompt 4：内容分层判断（所有选题→D层）
    ↓
Step 2.3  合规审查（P0/P1/P2三级检查）
    ↓
Step 2.4  Prompt 1：生成HTML商业报告（D层15模块+场景专属模块）
    ↓
Step 2.5  Prompt 2：HTML → PDF转换（Playwright+Chromium）
    ↓
Step 2.6  Prompt 3：生成小红书10天内容矩阵
          → Day1目录体 + Day2-9深度钩子 + Day10促单
    ↓
Step 2.7  生成manifest.json + 更新中转站状态
```

### 4.3 阶段三：情报产品生成

```
触发条件：opportunity_db有新增 / 每日定时 / 每周定时
    ↓
Prompt 5：日报生成（daily_brief_YYYYMMDD.json）
Prompt 6：周报生成（weekly_report_YYYYMMDD.json）
```

## 六、内容生产核心机制

### 6.1 D层报告结构（15基础模块+场景专属模块）

```
封面页 → 核心摘要 → 趋势背景分析 → 机会识别 → 数据对比(≥3表)
→ 可行性评估(含评分标准) → 机会推演 → 人群适配 → 典型案例
→ 可行性自评表 → 变现路径 → 竞争格局 → 启动成本
→ 风险提示+窗口期 → 免责声明
+ 场景专属深度模块
```

### 6.2 小红书10天漏斗模型

| 天数 | 类型 | 核心目的 | 价值引导 |
|------|------|---------|---------|
| Day1 | **目录体** | 建立完整价值认知，制造信息差 | "完整报告共X个模块" |
| Day2 | 深度钩子 | 数据规模深挖 | "完整数据在报告模块0X" |
| Day3 | 深度钩子 | 机会分析拆解 | "更多数据见报告模块0X" |
| Day4 | 深度钩子 | 变现路径（专属位置） | "完整变现路径在报告模块0X" |
| Day5 | 深度钩子 | 人群适配分析 | "你的策略在报告模块0X" |
| Day6 | 深度钩子 | 竞争格局分析 | "更多避坑见报告模块0X" |
| Day7 | 深度钩子 | 常见误区/避坑 | "你省的数据在报告模块0X" |
| Day8 | 深度钩子 | 启动成本明细 | "最新更新已加入报告" |
| Day9 | 深度钩子 | 案例拆解 | "XX人已用自评表做决定" |
| Day10 | **促单** | 行动框架+限时+会员引导 | "完整报告笔记下方获取" |

### 6.3 每天小红书输出文件

```
DayXX/
  ├── title.txt        ← 标题（≤22字）
  ├── cover.html       ← 封面HTML源文件
  ├── cover.png        ← 封面图片（1080×1440px，V8混合引擎生成）
  ├── note.md          ← 正文（可直接发布）
  ├── comments.txt     ← 10条互动评论
  └── images/
      ├── image_01.png ← 数据卡片
      ├── image_02.png ← 趋势分析
      ├── image_03.png ← 对比分析
      ├── image_04.png ← 步骤指南
      └── image_05.png ← 行动建议
```

### 6.4 V8混合引擎（图片生成）

图片生成采用三步流水线：

```
Step 1: Plotly生成数据图表 → base64编码
Step 2: base64嵌入HTML模板（HTML+CSS+内联图表）
Step 3: Playwright加载HTML → 截图为PNG（1080×1440px）
```

关键约束：
- Plotly图表必须设置`paper_bgcolor='rgba(0,0,0,0)'`透明背景
- Plotly fillcolor必须用rgba格式，禁止hex+alpha
- 主题色使用克制：accent-bg透明度0.06，accent-border透明度0.20
- 必须实际执行Python脚本，禁止只写代码不运行

## 七、数据库体系

### 7.1 三大数据库

| 数据库 | 内容 | 更新触发 |
|--------|------|---------|
| opportunity_db.json | RECOMMENDED副业机会（含评分历史） | 选题通过机会判断时 |
| risk_db.json | AVOID风险淘汰库+失效赛道 | 选题被AVOID时 / 趋势反转时 |
| trend_db.json | 各平台最新趋势信号 | 每次扫描发现新信号 / 每周趋势回顾 |

### 7.2 数据库冲突处理

- opportunity_db已有同名机会 → 不重复入库，更新last_verified和score_history
- risk_db已有同名风险 → 不重复入库，更新last_seen
- 两者都有 → 以最新verdict为准，胜者覆盖
- 冲突判断依据：副业方向名称关键词匹配度>80%

### 7.3 历史评分追踪

每个条目包含score_history数组，记录每次评估的日期、分数、判断结果。评分连续2次下降 → 自动标记"需重新评估"。

## 八、合规体系

### 8.1 三级合规检查

| 级别 | 触碰后果 | 检查内容 |
|------|---------|---------|
| P0 | 直接拒绝生产 | 黑五类/医疗诊断/违规导流/极限用语/涉政黄赌毒 |
| P1 | 降级处理 | 管制药品/成人用品/医美/虚拟货币/奶粉辅食/投资移民 |
| P2 | 修正措辞 | 医疗不推具体项目/金融无投资建议/教育无学科违规/不制造焦虑对立 |

### 8.2 D层免责声明（所有内容必须包含）

> 以上内容仅供参考，不构成投资建议。投资有风险，决策需谨慎。副业收入因人而异，不保证具体收益。创业有风险，请评估自身承受能力。本报告不构成任何形式的收益承诺或投资推荐。

### 8.3 小红书合规红线

- 禁止引导评论/关注/点赞/收藏（违规诱导互动）
- 禁止使用绝对化用语（最/100%/保证/稳赚）
- 禁止承诺具体收益（"月入过万"→"月收入天花板预估"）
- 禁止违规导流（加微信/QQ/私信我要链接）

## 九、选题生命周期

```
fresh → queued → consumed → archived

fresh:    刚生成，未被消费
queued:   已排入内容工厂队列，写入export/topic.json
consumed: 内容工厂已完成生产
archived: 已归档，移入archive/

超时规则：
- 7天未消费 → 标记expired
- 30天未消费 → 移入archive/并标记abandoned
- 季节性选题例外：peak期间或前30天内不标记expired/abandoned
```

## 十、去重机制

```
第1步：精确匹配 → topic_name完全相同 → 拒绝
第2步：关键词比对 → 3+个关键词相同 → 检查persona维度
第2.5步：persona维度 → persona不同则允许（不同人群选题）
第3步：角度比对 → 角度相同则拒绝，不同则允许
第4步：系列选题例外 → is_series:true允许主题相同，但series_episode必须递增
```
