## 一、架构决策说明

| 决策项 | 需求文档 | 实际采用 | 理由 |
|--------|---------|---------|------|
| 数据查询方式 | 静态优先（构建时生成JSON + Nginx直出） | **动态API**（FastAPI实时查询） | 当前数据量小（几百条），动态API响应毫秒级；静态方案增加运维复杂度，待用户量上来后作为Phase 2优化层 |
| FastAPI定位 | 仅鉴权（5%请求） | 鉴权 + 数据查询（100%请求） | 同上，动态方案开发效率更高 |
| 前端架构 | Vue.js SPA + 静态JSON | Vue.js SPA + 动态API调用 | 前端通过API获取数据，与后端完全解耦 |
| SSL证书 | Let's Encrypt (certbot) | **Cloudflare Flexible SSL** | 所有域名通过CF代理，CF边缘处理HTTPS，源站只需HTTP，无需certbot |
| 前端构建 | 服务器端 npm build | **本地构建 + 提交dist/** | 服务器仅2G内存，npm build会OOM卡死；本地构建后push dist，服务器git pull即可 |

### 5.3 部署方式（三种）

| 方式 | 触发 | 步骤 |
|------|------|------|
| **GitHub Actions CI/CD** | Push main 自动触发 | rsync → docker build → db migrate → restart → health check |
| **PowerShell 本地脚本** | 手动执行 `scripts/deploy.ps1` | git push → SSH pull → npm build → alembic → systemctl restart |
| **deploy.sh 服务器端** | 手动 SSH执行 | 支持 docker / native 两种模式，含全量安装 |

### 5.4 情报同步客户端集成方案

```
本地工作站 (Windows)
  ↓ git add . & git commit & git push origin main
  ↓
GitHub Actions CI/CD (自动)
  ↓ rsync + docker compose up -d
  ↓
远程主机 /opt/vuemonitor
  ├─ server/ (FastAPI)      ← /intel/sync/* 端点自动可用
  ├─ web-user/ (用户端)
  └─ web-admin/ (管理端)

情报数据同步（独立于代码部署）：
  商业情报中转站/
    ↓ python full_sync.py --base-url https://api.xhs365.cn --api-token $TOKEN
    ↓
  POST api.xhs365.cn/api/v1/intel/sync/*
    ↓
  PostgreSQL (intelligence_* 表)
```
