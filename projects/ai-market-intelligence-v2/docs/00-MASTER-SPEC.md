## 1. 背景与动机

### 1.1 问题

当前选品报告（V1）以 **离线 HTML + data.js** 形式交付，内含大量**可定位到具体商品/店铺**的原始字段（商品 ID、标题、店铺名、销量序列等）。从产品定位与合规角度，长期继续「售卖原始数据包」存在风险，且商业天花板有限。

### 1.2 目标

将产品从 **「爬虫 + 数据报告」** 升级为 **「AI 市场情报系统（AI Market Intelligence Platform）」**：

- **对内**：仍可采集、存储、计算（原材料仓库）
- **对外**：只输出聚合指标 + AI 洞察 + 决策建议，**不以产品功能为目的**公开、导出或分发可定位经营者的原始数据

### 1.3 一句话核心理念

> **数据是原料，算法是能力，AI 是产品，情报才是价值。**

### 1.4 参考讨论来源

- ChatGPT 对话主题：《爬虫数据合规风险》→ AI 市场情报系统 V2.0
- 近期工程讨论：会员页授权码续费、选品报告中心 `monitor.xhs365.cn/member`、PC 端 ProductAnalyzer

## 3. 双轨策略：在期买家与 V2 并行

### 3.1 原则

**不能一刀切关停 V1。** 尚未服务完的买家，须在其**已购周期内**继续获得 V1 形态报告。

### 3.2 阶段划分

| 阶段 | 时间 | V1（现网） | V2（实验室） |
|------|------|------------|--------------|
| **Phase 0** | 现在 | 正常运行 | 只写文档 + 本地原型 |
| **Phase 1** | 文档完成后 | 正常运行 | 本地 Web 验证架构 |
| **Phase 2** | 内部验证 | 正常运行 | Shadow 管道（内部对照，不对外） |
| **Phase 3** | 在期买家履约 | 仅维护，不新签 V1 数据包 | 新会员只签 V2 |
| **Phase 4** | 切换 | 到期自然下线 | 选品报告中心升级 V2 |

### 3.3 会员合同/Product SKU 建议

| SKU | 对外名称 | 交付物 |
|-----|----------|--------|
| V1-Legacy | 选品数据报告（Legacy） | 现有 zip + data.js（仅履约期） |
| V2-Pro | AI 市场情报报告 | HTML/PDF 情报页，无原始商品表 |
| V2-Enterprise | 多赛道情报 + 定制 | 多类目 Agent 报告 |

### 3.4 技术隔离要求

- V2 代码、数据库 schema、API **独立命名空间**（如 `insight_*` 表前缀）
- V2 本地原型目录：`projects/ai-market-intelligence-v2/`
- **禁止** Phase 0～1 向 `/opt/xhs-cloud` 部署任何 V2 实验代码

## 5. 六层系统架构（严格隔离）

```
                    用户
                      ↑
         ┌────────────────────────────┐
         │  L6  AI 市场情报报告       │  ← 用户唯一可见输出
         └────────────────────────────┘
                      ↑
         ┌────────────────────────────┐
         │  L5  AI 咨询分析中心       │  ← 多 Agent + Prompt
         └────────────────────────────┘
                      ↑
         ┌────────────────────────────┐
         │  L4  指标 / 趋势分析引擎   │  ← 自研指数体系
         └────────────────────────────┘
                      ↑
         ┌────────────────────────────┐
         │  L3  数据标准化处理层       │  ← 原始 → 指标
         └────────────────────────────┘
                      ↑
         ┌────────────────────────────┐
         │  L2  数据采集层（内部）     │  ← 不对外
         └────────────────────────────┘
                      ↑
         ┌────────────────────────────┐
         │  L1  公开页面（用户授权）   │
         └────────────────────────────┘
```

**层间规则**：上层只能消费下层**已脱敏、已聚合**的输出；L2 原始数据**永不出库**到 L6。

## 6. 各层详细设计

### 6.1 L1 — 公开页面（用户授权）

- 用户在自己设备上浏览小红书公开页面
- PC 助手定位：**研究工具**，非批量分发器
- 用户主动添加「关注类目 / 关注方向」，而非系统灌入全量商品表

### 6.2 L2 — 数据采集层（内部）

**原则：永远不要把原始数据作为产品。**

内部库可存（仅内部）：

| 字段类型 | 示例 |
|----------|------|
| 标识 | 商品 ID、店铺 ID（内部主键，禁止 export） |
| 快照 | 价格、销量、收藏、加购、标题、图片 URL |
| 时间 | 发布时间、采集时间、上架时间 |
| 文本 | 标题、类目标签（内部 NLP 用） |

**禁止**：导出、开放查询、开放下载、对外 API。

### 6.3 L3 — 数据标准化

**不让 AI 看原始序列。** 先计算指标再上行。

| 原始 | 标准化输出 |
|------|------------|
| 销量 1289→1301→1400→1450 | 增长率 +12%、趋势「持续上涨」 |
| 发布时间 7 天前 | 新品指数 92 |
| 价格 19.9 | 价格带 10～20 元 |
| 多 SKU 竞争数 | 竞争指数 18（0～100） |

输出形态：**类目 × 时间窗口** 的指标 JSON，无商品 ID。

## 7. 指标体系（核心竞争力）

V2 对外卖的是**指数**，不是商品列表。

### 7.1 建议指数清单

| 指数 | 英文名 | 输入因子 | 输出 |
|------|--------|----------|------|
| 热度指数 | `heat_score` | 销量增速、收藏、加购、搜索热度 | 0～100 |
| 新品指数 | `new_product_score` | 上架时长、早期增速 | 0～100 |
| 蓝海指数 | `blue_ocean_score` | 需求、竞争密度、新品涌入 | 0～100 |
| 生命周期指数 | `lifecycle_stage` | AI + 规则 | 新品/成长/成熟/衰退 |
| 季节指数 | `season_score` | 类目 + 日历 | ★1～5 或 0～100 |
| AI 机会指数 | `opportunity_score` | 多指数加权 + AI | 0～100 + 一句话 |

### 7.2 指数计算原则

1. **类目级 / 价格带级 / 时间窗口级** 聚合，最小粒度不得细到可反查单店
2. 所有公式版本化（`index_formula_version`），可回放
3. 原始快照参与计算后，报告层只存指标结果

### 7.3 示例：标准化指标 JSON（L4 → L5）

```json
{
  "report_date": "2026-07-12",
  "category": "小学教辅",
  "sub_category": "暑假衔接",
  "window_days": 7,
  "metrics": {
    "growth_rate_pct": 42,
    "competition_index": 18,
    "blue_ocean_score": 89,
    "heat_score": 76,
    "new_product_score": 65,
    "lifecycle_stage": "成长",
    "season_score": 5,
    "price_band": "9-19",
    "trend_label": "连续上涨"
  },
  "disclaimer": "本报告基于公开市场趋势归纳，不构成对特定商品或店铺的建议。"
}
```

## 8. AI 分析中心与多智能体

### 8.1 AI 输入约束

**禁止进入 Prompt 的字段：**

- 商品 ID、店铺 ID、商品名称、店铺名称、商品图片 URL、可点击商品链接

**允许进入 Prompt 的字段：**

- 类目、增长率、竞争指数、蓝海指数、价格带、趋势标签、季节因子

### 8.2 统一 Prompt 角色

```
你是一名市场咨询顾问。
基于以下【类目级指标】输出：趋势、原因、建议、风险、是否值得进入。
禁止输出任何可定位到具体商品、店铺或经营者的信息。
禁止编造未提供的数字。
```

### 8.3 多 Agent 分工

| Agent | 职责 | 输出 |
|-------|------|------|
| **市场分析师** | 行业趋势、宏观方向 | `trend_summary` |
| **数据分析师** | 解读增长率、指数 | `metric_interpretation` |
| **电商运营顾问** | 怎么做、定价、内容形式 | `action_plan` |
| **风险分析师** | 红海、政策、季节风险 | `risk_assessment` |
| **CEO 总结** | 一句话决策 | `executive_summary` |

### 8.4 Agent 编排（建议）

```
指标 JSON
  → 并行：市场分析 + 数据分析 + 风险分析
  → 串行：运营顾问（消费前三者摘要）
  → 串行：CEO 总结
  → 渲染：L6 HTML/PDF 报告
```

### 8.5 工程参数（PRD 级，待细化到 07/08 文档）

| 参数 | 建议值 |
|------|--------|
| 模型 | GLM-4/5、Claude、GPT（可配置） |
| 超时 | 30s / Agent |
| 重试 | 3 次，指数退避 |
| 缓存 | Redis，key = hash(指标JSON + prompt_version) |
| 失败降级 | 仅输出规则模板报告，标记 `ai_status=degraded` |

## 9. 用户可见的最终报告形态

### 9.1 报告禁止出现

- ❌ 商品 ID、店铺 ID、店铺名称、商品链接、商品 URL
- ❌ 可定位经营者的信息
- ❌ 可下载的原始 data.js 全量商品表

### 9.2 建议报告结构（6 页式）

| 页 | 标题 | 内容示例 |
|----|------|----------|
| 1 | 本周趋势评分 | ★★★★★ + 一句话 |
| 2 | AI 总结 | 「最近 7 天，小学教辅增长明显，暑假衔接需求持续…」 |
| 3 | 市场机会 | 增长 42%、竞争中、机会 ★★★★★ |
| 4 | AI 建议 | 建议进入：小学语文；价格带 9～19；内容形式 PDF/资料包 |
| 5 | 风险提示 | 竞争开始增加，建议 7 天内完成布局 |
| 6 | 总结 | 适合进入 / 观望 / 不建议 |

### 9.3 交付格式

- 主：**在线 HTML 情报页**（会员中心内嵌，不可导出原始表）
- 辅：**PDF 摘要**（Pro+）
- 禁止：zip 内含可解析全量商品 JSON

## 13. 合规边界设计（Compliance by Design）

### 13.1 固定规则（写入所有子文档）

> 内部系统可以处理公开来源的数据用于统计、建模和趋势分析；**对外产品默认只输出**经过聚合、归纳和 AI 分析后的市场情报，**不以产品功能为目的**公开、导出或分发可直接定位到具体商品、店铺或经营者的原始数据。

### 13.2 开发检查清单

- [ ] 对外 API 响应中无 `goods_id` / `store_id` / 完整标题
- [ ] 对外报告不可下载含 positional 商品数组的 data.js
- [ ] 日志脱敏：生产日志不打印完整标题/ID
- [ ] AI Prompt 审计：自动扫描 Prompt 输入是否含禁用字段
- [ ] 导出功能：V2 仅 PDF/HTML，无 CSV 全量商品

### 13.3 产品设计阶段即约束

合规不是上线后补丁，而是 **L4 指标层 + L6 报告层** 的硬约束。

## 14. 为什么「十二点架构」不够：十层设计

ChatGPT 讨论的「十二点」属于 **Business / Product Architecture（60～70 分）**。  
要让大模型**直接开发可用代码**，还需要以下层次：

| 层 | 名称 | 受众 | 产出物 |
|----|------|------|--------|
| 1 | 商业架构 | CEO | 定位、卖什么、价值主张 |
| 2 | 产品架构 | 产品 | 模块拆分、用户旅程 |
| 3 | 需求设计 PRD | 程序员 | 输入输出 JSON、异常、超时 |
| 4 | 数据库设计 | 后端 | ER、表字段、索引 |
| 5 | 接口设计 API | 前后端 | REST/任务型 API |
| 6 | AI Agent 设计 | AI 工程 | Agent 图、Prompt、模型 |
| 7 | 页面原型 | 产品 | 线框、按钮、流程 |
| 8 | UI 设计 | 设计 | 色板、字体、组件 |
| 9 | 开发架构 | 架构 | 技术栈、目录、依赖 |
| 10 | 部署 | 运维 | 环境、CI、发布 |

### 17.1 目标

在 `projects/ai-market-intelligence-v2/local-web-prototype/` 用静态或轻量 FastAPI：

3. 渲染 6 页情报报告 HTML
